# Cloned Repositories

8 repositories, all cloned `--depth 1`. No repository was specified by the research topic
(there was no `code_references` section), so all of these were found through the literature.

None is required as a runtime dependency: each is used either as a **data source** or as a
**reference implementation** to port from. Nothing here needs to install cleanly for the
experiments to run.

| Repo | Location | Size | Why it's here |
|---|---|---|---|
| CLAMBER | `clamber/` | 984 KB | Data: 3,202 balanced ask-vs-answer items |
| Mistral-Interact | `mistral_interact/` | 15 MB | Data: IN3 vagueness + importance-rated missing details |
| human-eval-comm | `humanevalcomm/` | 2.0 MB | Data + metric: executable cost of not asking |
| ClariQ | `clariq/` | 555 MB | Data: graded `clarification_need` 1–4 |
| ClarEval | `clareval/` | 5.4 MB | Data: fuzzy code specs, single- and multi-turn |
| ask-or-assume | `ask_or_assume/` | 108 MB | Data: SWE-bench underspecification × difficulty |
| AbstentionBench | `abstentionbench/` | 1.5 MB | Reference: abstention eval harness + published results |
| RegretBench | `regretbench/` | 47 MB | Reference: regret-based multi-turn clarification metric |

## Data sources

### `clamber/` — <https://github.com/zt991211/CLAMBER>
Single payload: `clamber_benchmark.jsonl` (3,202 items). **Lines are double-JSON-encoded**
(each line is a JSON string wrapping a JSON object). A normalized single-encoded copy is staged
at `datasets/clamber/clamber_benchmark.jsonl`; prefer that one.

### `mistral_interact/` — <https://github.com/HBX-hbx/Mistral-Interact>
`data/IN3/{train,test}.jsonl` is the piece that matters (1,261 / 108). Also ships
`data/interactions/` (8.5 MB of training interactions) and `data/user_interaction_records/`
(per-model transcripts for Llama-2-7b-chat, Mistral-7B-Instruct-v0.2, and their own
mistral-interact) — usable as human-baseline reference trajectories.

### `humanevalcomm/` — <https://github.com/jie-jw-wu/human-eval-comm>
`Benchmark/HumanEvalComm.jsonl` plus `_v1`/`_v2` variants in JSON/JSONL/CSV. Also
`auto_modified_problems/` showing how the perturbations were generated — worth reading if you
want to extend the perturbation set rather than only consume it. The `test_case` field is what
makes the downstream cost executable.

### `clariq/` — <https://github.com/aliannejadi/ClariQ>
555 MB, almost entirely git history and retrieval indices. Only `data/*.tsv` is needed and those
are staged into `datasets/clariq/`. If disk matters, this clone can be deleted after staging.

### `clareval/` — <https://github.com/JialinLi13/ClarEval>
`data_synthesis/` holds the benchmarks. Note `total_final_data/final_data.jsonl` is **0 bytes**
in the published repo — use `single_turn_benchmark.jsonl` / `multi_turn_benchmark.jsonl`
(492 each) instead. Two larger LiveCodeBench-derived files (`lcb_*.jsonl`, ~6 MB each) are also
present.

### `ask_or_assume/` — <https://github.com/nedwards99/ask-or-assume>
A full OpenHands-based agent application (frontend + backend); we use only
`analysis/swe-bench-annotation-results/ensembled_annotations_public.csv` (1,699 rows). The
`analysis/original_paper_results/` directory documents how their published numbers were rebuilt,
which is useful if you want to compare against their reported baselines rather than re-run them.

## Reference implementations

### `abstentionbench/` — <https://github.com/facebookresearch/AbstentionBench>
Harness for evaluating abstention across 20 datasets and 6 scenarios.

- **Directly usable with no setup**: `analysis/abstention_performance.csv` (66 KB) — published
  per-model, per-dataset abstention results. This is a free comparison point.
- **Data loading is blocked here**: the HF repo is a loading script, unsupported by
  `datasets>=4`. To rebuild the component datasets, use a **separate** venv with
  `datasets==3.6.0` (do not downgrade this workspace — the other loaders need v4).
- **Worth porting**: `recipe/evaluation_judge_prompts.py` and `recipe/abstention_keywords.py`.
  The keyword list gives a cheap, deterministic abstention detector, and the judge prompts are
  human-validated — reusing them is better than inventing an abstention classifier, and it makes
  results comparable to their published numbers.
- Their headline finding is directly relevant: reasoning fine-tuning *hurts* abstention
  (~24% degradation), so reasoning-tuned models should not be assumed to be the strong baseline.

### `regretbench/` — <https://github.com/ngocminhta/RegretBench>
Multi-turn clarification evaluated as a **policy**, scored by regret against a reference
clarification policy. Ships only `data/*/manifest.json` — episodes are generated by running the
harness (OpenDomainQA and ProductRecommendation scenarios), so it is not a static dataset.

Worth borrowing conceptually even without running it: it decomposes clarification quality into
intent resolution, interaction cost, ineffective clarification, and regret. That decomposition
is what separates "asked a plausible question" from "asked the right question at the right
time", which single-turn accuracy cannot distinguish.

## Status check

These are data/reference clones, not dependencies — no installation was attempted, and none is
needed. The two repos whose harnesses one *might* want to execute are noted honestly above:
AbstentionBench needs a `datasets==3.6.0` sidecar venv, and RegretBench generates its episodes
at runtime rather than shipping them.
